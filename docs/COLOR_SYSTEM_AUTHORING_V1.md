# Authored color construction and composition

The candidate authoring workflow connects source intake, scale construction, refinement, durable recipes and exact delivery. Local integration and independent review are recorded in the [workflow receipt](evidence/2026-09-24-authoring-workflow.md) and [delivery receipt](evidence/2026-09-24-authored-delivery.md). Final performance repetition, real-brand evaluation and full release gates remain required by the PRD. Native delivery has local mock-host verification; current Figma-host acceptance remains unobserved. Production exposure stays disabled and qualification stays false.

## Preserve the source, record the proposal

`colorSystemProposalV1` keeps the original model separate from a working proposal. The brief names the contexts, modes, operation and allowed additions or structure edits. Applying a system permits no added values, families, scales or rules. An extension can add permitted values without changing an original color. Additive structure edits retain every original member, ordered slot, mode and anchor.

Changed rule dependencies invalidate the affected adoption. A fresh review binds the exact proposal hash and records its actor, authority and decision. Replacing a source rule requires an explicit exception with a rejected original and accepted replacement in the same attributed decision. Because adoption currently covers an entire rule, replacement must cover all of its original contexts and modes. A narrower exception fails explicitly; it cannot disable the original elsewhere. The original remains inspectable. Proposal lineage is declared evidence; only a recomputing executor can establish that the claimed construction actually ran.

A direction may separately declare a provisional agent review for enumerated, previously accepted source predicates. Its policy binds the exact source, generation request, complete brief and permissions, and explicitly declares whole-predicate decision scope. After one generation, the existing proposal builder binds fresh decisions to the unchanged predicates and actual generated dependencies. The receipt retains every renewed rule's complete contexts, modes and hashes alongside the original generation. This is agent review, not owner approval. Refinement invalidates the policy. Pending rules found in actual attempted applications remain visible even when the search reaches its limit.

## Build only the requested scale

`colorSystemConstructionV1` interpolates requested gaps between fixed native anchors at their actual authored positions. It retains separate scales within a family and separately requested modes. Missing numeric source authority remains a gap; the constructor does not interpolate across it. Outer endpoints require explicit proposed values and permission. A requested lightness order that conflicts with fixed pins returns infeasible.

The constructor uses the existing gamut mapping algorithm before display-hex rounding. For nearly identical native anchors, a documented native-sRGB precision fallback avoids conversion noise moving an interpolated value outside the pins; the final native ordering check still applies. It changes no recorded source value. The old byte-based mapper retains its output contract.

`colorSystemConstructionProposalV1` recomputes this construction and materializes the resulting additions under the brief's family/scale permissions. Generated slot identities remain stable across explicitly requested modes. Incomplete, infeasible or cancelled construction returns no proposal. Its receipt retains exact source and generated origins, interpolation bounds, gamut mapping and input hashes.

## Use the libraries as distinct sources

`colorSystemCatalogCandidatesV1` retrieves bounded whole Wada combinations, individual Werner references and exact Radix families. It uses recorded anchors and explicit mode mapping. Retrieval distance is matching evidence, not a score for design quality or application feasibility. Historical digital approximations retain that label. Radix values and all twelve steps remain unchanged.

The catalog materializer recomputes actual proposed colors from enabled providers, with query, catalog, policy and candidate identities attached. The final gate must still assess those colors against the brand and complete applications. Disabling a provider must remove its actual proposals without silently replacing their provenance.

## Compose complete applications

`colorSystemApplicationRequirementsV1` fixes the requested actual paints, roles, areas, pair checks, grounds, modes and exact color locks. It rejects missing states, weakened thresholds and a reduced chart count. Distinction groups must name an actual ground used by every member. Modeled color-vision separation is labeled Teul policy evidence; it is not a WCAG criterion or a guarantee of perception.

`colorSystemModelCompositionV1` searches explicit groups of alternatives. An option may couple several uses, preserving a whole pairing or selected state set. Every option in a group owns the same targets, and the groups cover every requested use exactly once. The composer first rejects known failing contrast pairs using the same native compositing helper as final assessment, then runs the full relationship and application checks. It returns complete applications and selected option identities. A missing source value, exhausted search budget, cancellation and demonstrated failure of the available choices remain different results.

The authored interaction selector reuses the old selector's kernel while allowing several scales in one family, up to 64 members, explicit order/preferences and exact state locks. The model adapter maps authored slot positions to ordinal indices for selection and returns the original positions and IDs. That mapping preserves fractional spacing and source identity; it does not invent Radix steps or approval. Complete source, application and territory checks still follow selection.

## Gate first, compare second

`colorSystemAuthoredCandidatesV1` rebuilds each declared proposal and assesses its complete applications before ranking. Every proposed value requires a scoped construction unit. Accepted restrictions test its explicit representative anchor and jobs; exclusions test every recorded member, including unpainted additions. A proposed paint used in another context must have a unit in that context. These checks retain the existing territory semantics.

Comparisons require the same brief and change permissions. The gate keeps both the original-source assessment and the reviewed working assessment. It prefers fewer unsatisfied accepted preferences, then fewer added colors, with stable identity as the tie-break. It displays at most three feasible directions and suppresses variants without a material actual-paint difference. Translucent paints are compared on their recorded grounds. These are inspectable selection heuristics, not aesthetic approval.

The executor first checks the preferred state combination in the complete application. The executor enumerates bounded coherent alternatives when that preferred combination fails: preferences cannot act as hard locks. A truncated alternative search must report its limit rather than claim that no permitted solution exists.

## Refine and resume a design

The candidate's Source relationships view reads a source model or reopens a recipe. The product-scale form asks for the context, authored modes, source anchor, actual surface, text and focus colors. It compiles those choices into the existing constructor and complete-application checks. Its fixed control, link and selected-control samples are Teul's explicit test policy. They do not infer product permission from a brand guideline.

Custom systems enter through a recipe import or advanced direction JSON. Supported overlay recipes expose ordinary controls for replacing catalog fragments and editing proposed role bindings. A replacement shows actual catalog values and asks for each affected color, family and scale mapping. Missing mappings, unavailable replacement structures, stale identities and edits into another construction fail explicitly. Other contextual rule kinds remain inspectable and reviewable; they do not yet have dedicated form editors.

An overlay retains the original source and replays bounded construction, catalog and rule fragments against it. It combines their additions once, preserving each provider receipt, then assesses complete applications. Proposed rules remain pending until an explicit attributed review. Construction and catalog origins are independent; rule-only fragments attribute each rule separately. An edit never renews an unrelated adoption merely because the two rules appeared in the same fragment. Exact dependency checks still invalidate decisions when the referenced values, relationships or evidence change.

Family and scale locks bind native values, authored memberships and governing relationships. A failed or cancelled revision retains the last confirmed selection. Content identity excludes execution timing and insignificant runtime contrast noise; fresh measurements remain in the execution receipt. Imported intent-only drafts become explicitly unsaved selected designs after successful recomputation.

Recipes contain source snapshots, declared intent, selected model/applications, decisions and locks. They contain no write permission or execution-session capability. Backend storage uses immutable revisions with parent hashes and confirmed readback. It permits eight active recipes, 64 data revisions and 4 MiB of aggregate recipe data; capacity errors never evict earlier work. Concurrent branches remain visible for an explicit choice. Deletion records a durable tombstone before cleaning up known revisions, with a separate bounded tombstone reserve.

Raw recipe import/export permits up to 8 MiB and preserves the original bytes of safe unknown versions for read-only export. Raw data crosses the message boundary directly, avoiding nested JSON escaping that would otherwise reduce the supported size. Saving remains subject to the separate storage budget. Saved intent never restores source freshness: a current-file check must resolve the recorded scope through an actual backend read and compare the full native model. Imported guidelines remain reviewed snapshots. The read check does not change Figma selection or viewport and grants no Create authority.

To keep both interface bundles within their existing budgets, the unchanged 65-preset grid catalog now loads from the local plugin backend. A program-owned content pin verifies every serialized preset and provenance field. The interface exposes loading/retry, validates the response's source and request identity, and retains offline operation.

## Remaining verification

Focused tests cover immutable pins/modes, impossible locks, source gaps, permissions, stale reviews, exact libraries, complete-state checks, actual-ground distinctions, bounded search and detached replay. Independent reviewers found and repaired several integration errors; those regressions remain in the tests.

The generalized selector's maximum admitted 24-by-64 search was observed at about nine seconds with its default timer scheduler, while its longest synchronous segment in that probe was about 20 ms. That probe establishes neither the PRD's complete-workflow performance target nor a blanket two-second claim. The fixed 100-color, 50-rule, two-mode workload is frozen and independently inspected. Its first 30-run measurement failed at 3,609 ms p95; the final reviewed TASK-005 source passes at 1,885 ms with unchanged completed output. Seven cancellation probes pass, with a maximum of 139 ms. The [measurement ledger](evidence/2026-09-24-authoring-performance.md) preserves failures, exact executable/input identities and limits. Integrated performance, real-brand evaluation and current Figma-host observation remain separate gates. Browser DOM checks and synthetic native-host tests do not establish Figma or screen-reader acceptance.
