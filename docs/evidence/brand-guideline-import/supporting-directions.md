# Supporting-color adapter for reviewed guidelines

The imported-model adapter can propose a new supporting paint from a selected catalog while retaining exact source colors, families and decisions. It reuses Teul's catalog materializer, complete application checks, measured geometry, diversity filter and portable delivery. This is partial TASK-007 / REQ-008 evidence. Studio controls and saved-project integration are the next implementation step; the adapter is not yet exposed in the interface.

## Behavior

The request names one source mode and context, one through eight opaque reference colors, fixed source paints, a catalog and candidate exclusions. Historical colors retain their digital-approximation disclosures. Radix requires an explicit light/dark mapping and retains its exact-library identity. No imported source scale is replaced or forced to have twelve steps.

A request retrieves at most eight catalog families. For a brand composition, it chooses one new paint per family and places it beside the fixed source colors in the existing measured split, frame or stack layout. The selected paint itself is the generation anchor checked against source territories. A Wada companion is an unmatched member of a documented catalog combination. That documents the historical reference relationship, not compatibility with the imported brand. The nearest-source distances remain inspectable, with no claim of a universal compatibility threshold.

Product suggestions use exact Radix families. Published step 9 is fixed as the new rest paint; the existing state selector proposes distinct hover and pressed values and checks them in complete applications. Focus retains rest with an explicit source ring. Disabled fill and label are separate source choices. Every displayed state also contains the fixed source ground and secondary link. Historical automatic control states are unsupported in this adapter; manual applications remain available.

The existing engine admits at most three materially different eligible directions after checking actual applications. The source distance ordering uses the existing canonical numeric rounding before comparisons. These checks establish eligibility and difference, not beauty or usefulness. Only one brand paint per retrieved family is tested; an empty result does not prove that every possible catalog paint or color system is impossible.

## Source rules and recovery

A source-wide closed-palette requirement remains blocking without a separately designed exception. Other conflicts, missing values and rule decisions are checked by the application engine against actual consumers. An unused unresolved alias remains in the model and does not block unrelated valid paint. Using it as a reference is rejected.

This catalog path adds separate source and family records and does not edit existing structures. It therefore requires all existing adoptions to remain byte-identical. Unexpected changes fail closed; the adapter cannot renew or reject source decisions. The earlier speculative proposal-review API was removed after inspecting the exact dependency behavior.

Cancellation yields between candidate materializations and inside the existing engine. A cancelled run returns no partial comparison. Exports require a captured eligible result and rerun the shared delivery checks. CSS/JSON and measured SVG use the exact selected model and applications. Copied result objects cannot grant export authority.

The versioned supporting-color file binds source/review identity, request, selected recipe and catalog provenance. Reopening recomputes eligibility and compares all authored recipe content and provenance. Stable design-content IDs identify selected paint across runtime-specific assessment IDs and shortlist changes. The old numeric execution receipt is replaced by the fresh execution; its hash is never treated as saved authority. If the retained eligible choice is now outside the comparison, reopening returns that single chosen direction.

A regression case changes fresh numeric candidate IDs and removes the old choice from the shortlist; reopening and SVG export still preserve the exact eligible design. The existing extension tests cover the unchanged default behavior of the extracted shared preflight.

Independent reuse, quality and efficiency reviews led to canonical distance decisions, cached source/member distances, cancellation between materializations and stable saved-design identity. These are synthetic engineering checks. No human visual acceptance, browser comparison UI, live connector qualification, native Figma paste observation, integration, push or deployment is claimed.
