# Audit remediation — plan of action and outcomes (2026-09-07)

Status: complete, including Phase 3, on branch `audit-remediation-2026-09-07`. Source: a read-only audit of the plugin
completed earlier the same day (seven workstreams: product model, change review, color-math
verification, extension-feature intelligence, engineering quality, expert benchmark, UX). Its
verdict: the arithmetic and the engineering discipline were sound; the color idea inside the
extension feature was weak (a fixed six-spoke hue wheel at the primary’s lightness); two defects
blocked real use (an unscrollable builder panel; Dark mode composed as light with hue-arbitrary
semantic roles).

Verification runs locally with `npm run release-gate` on Node 22 and Node 24; receipts live under
`docs/evidence/gates/`. GitHub Actions is not used.

## Out of scope, and why

- Purging private identifiers from public git history: owner decision (fix-forward is done).
- Deleting the V1 audit program’s source (about 21,000 lines): owner decision; it no longer ships.
- Live Figma validation (AC-909, host checks, Community publication): requires a human in Figma.
- Pantone values: licensed data, never generated; the model carries an owner-supplied field.

## Follow-ups worth a decision

- The generic planner fills a fixed number of accent slots per direction because brief integrity
  requires one family count across directions; an adaptive count (as the governed private path had)
  needs a contract change.
- Status roles follow each strategy’s accents; when the brand owns no green or red hue the composer
  uses the nearest hue and records a warning. A “reserved status hues” option would let a team pin
  conventional greens and reds independent of the brand.
- Categorical marks in Dark mode can fall short of the request for analogous strategies; the UI now
  reports the achieved count. Whether Close Harmony should offer data-viz at all is a product call.

## Close-out (2026-09-09)

The owner reviewed the private-brand runs and rejected the generated accents (“The brand would never use magenta
as a secondary color”). The planner’s strategies are colour math (complement of Solar → magentas and
violets) with no brand-taste input; the engineering is correct and the proposal is off-brand. The
next requirement, if this tool is to propose accents for that brand, is a **brand-territory input**: hue
ranges and a chroma ceiling derived from the recorded secondaries or set by the owner, applied as the
planner’s search territory (the engine’s territory gate exists; the generic path sets it to the whole
wheel). Until then, _Extend_ is the honest choice for that brand. Shipping line: `main` on the owner’s
private repository; receipts under `docs/evidence/gates/`.
