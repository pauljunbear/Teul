# Teul Studio

A standalone React + shadcn interface over Teul's existing color engines. Start with brand swatches, compare complete product directions, and carry the selected recipe through preview, saving and semantic export. Color scales, exact Radix families, 348 Wada combinations, 110 Werner colors and standalone contrast remain available.

## Run from the full repository

Use Node 22.13+ or Node 24 with npm 10. The adapter imports shared source from `../src`; `web/` is not an independent source checkout.

```sh
npm ci
npm --prefix web ci
npm --prefix web run dev
```

## Verify and build

From the repository root, `npm run verify:local` runs the plugin release gate and Studio checks together, starts its own temporary preview/development servers, and records a receipt under `docs/evidence/local-gates/`. It always tests this checkout and its build, ignoring inherited `STUDIO_URL` and `STUDIO_DEV_URL`; individual browser commands retain those overrides. Use `STUDIO_CHROME` to select an installed Chrome. Repeat on Node 22 and 24 for shared-core changes. The command leaves an already-running feedback session alone. `npm run verify:local -- --dry-run` lists its checks.

Add `--guidelines` to include intake audit/lint/tests, a separate Guidelines-enabled build and the existing import, review, generation, storage, refresh and performance suites. For the standalone tool, run `npm run verify:local -- --studio-only --guidelines` on Node 22 and Node 24. Normal and enabled builds have separate artifact manifests; changed build files fail the run. Browser harnesses run sequentially. The runner pins feature flags and the 30-repeat gradient workload, closes its old servers before changing profiles and records the managed browser evidence per run. Individual adapter harnesses retain their documented production/development distinction.

This local fixture profile does not qualify a live service or supply human design/accessibility approval. The separate `proof:guideline-application` experiment needs the admitted, hash-pinned `release/guideline-proof/katalon.pdf`; it is not a clean-checkout regression dependency. Real-source corpus/evaluation work remains in the acceptance inventory.

For a Studio-only iteration:

```sh
npm --prefix web run lint
npm --prefix web test
npm --prefix web audit
npm --prefix web run build
npm --prefix web run preview -- --host 127.0.0.1 --port 5179
```

In a second terminal, install Chromium once with `cd web && npx playwright install chromium`, then run `npm run test:browser`. To use an installed Chrome, set `STUDIO_CHROME` to its executable. Optional `STUDIO_URL` and `STUDIO_EVIDENCE` select the preview address and screenshot/report directory. The default evidence folder is the ignored repository `release/` directory.

Run `npm run test:feedback` from `web/` against the same production preview for the recording-feedback regressions: library selection, contextual suggestions, exact Radix match evidence, automatic loading, saved palettes, contrast pairs, and the 390px layout. These scenarios also verify that Agentation stays out of production.

The build emits a static `dist/` with a healthcheck and license notices. Generation uses no server, credentials or external service. Font files are self-hosted. Saved work uses the browser's IndexedDB database; it is not synced between devices. Clearing site data deletes it.

### Recovering interrupted guideline requests

Before dispatch, Studio retains the original request and, for PDF assistance, the complete workspace snapshot and any selected evidence images in a separate temporary browser cache. **Saved assistance/Figma/website requests → Check saved requests** verifies the signed-in intake-service account and lists its retained requests. **Open saved request** explicitly restores the earlier PDF workspace or reads the existing capture. Recovery uses the old job ID or hash-only lookup; it never repeats a submission. Closing Studio or editing the source stops local waiting. Use the explicit cancel control to stop remote work. Completed requests remain recoverable after applying suggestions.

This cache is not encrypted account storage. It holds at most eight requests, 32 MiB each and 64 MiB total. Known records expire after 24 hours and are removed when Studio next opens/checks the cache. **Remove local copy** deletes only the temporary browser evidence; separately saved projects and remote work are unchanged. A full or unavailable cache blocks new dispatch without deleting existing evidence. Another tab changing/removing a request blocks stale restoration. Save or download any workspace you want to retain longer.

`npm --prefix web run test:guideline-recovery-storage` tests real IndexedDB transactions, cross-tab changes, quota failure, expiry and corruption. Assistance, Figma and website browser journeys test reload recovery. See [durable recovery evidence](../docs/evidence/brand-guideline-import/durable-job-recovery.md).

## Source and accessibility boundaries

The separate **Color scales** workflow uses the source model → scale plan → construction proposal APIs. Each completed legacy scale retains its original at step 9 in light and dark modes. Partial failures are shown and omitted from exported families; original input metadata remains intact. The production-default Studio accepts swatches only. The development guideline proof is described above; neither workflow certifies aesthetic or brand compliance.

Custom Radix matching finds the nearest published accent family and displays the actual matched light/dark step beside your reference. Its neutral follows the matched family. Choosing a named family from Library loads that exact family, including neutrals. Gold is the published muted brown scale; Amber is a separate yellow-orange scale. Generated, exact Radix, and historical digital approximations carry distinct labels and export metadata. Wada combinations come from reverse-indexing the admitted data; Werner uses the audited transcription module.

Add or replace individual colors through Suggested, Wada, Werner, Radix, or Custom in the color picker. Suggested companions come from the existing Wada catalog, using every current input as a reference. The picker shows each candidate alongside your colors and identifies its source combination; it does not certify harmony or accessibility. Distant matches produce an empty state, with library and manual choices still available. The Library loads additional entries while scrolling and retains a keyboard button. Saved opens device-local recipes directly.

The Color scales preview measures the displayed foreground/background pairs; it does not assess a complete component application. Product system uses the complete-state assessment described above. Neither certifies a finished product. APCA is supplemental; WCAG 2.2 drives pass/fail results. Scale JSON exports preserve provenance and diagnostics. Scale Tailwind exports use the existing Teul CommonJS configuration format; CSS variables work independently of a Tailwind version.

## Deploy and roll back

Build locally and deploy the contents of `dist/` to any static host. No server or managed database is needed. Check `/healthcheck`, render the live app, and verify a generated result. Keep the previous build for rollback.

Plugin production/candidate bundles are separate artifacts. Shared catalog or color-core changes require both runtime gates; `verify:local` runs the existing plugin gate and the Studio suite in one command. Dead-code reporting follows production, candidate and Studio entrypoints, including aliases and dynamic imports; its candidates still require consumer review before deletion. No hosted CI is added.

Components were installed through [the official shadcn CLI](https://ui.shadcn.com/docs/installation/vite) (Radix Nova preset). `components.json` records their source configuration. `scripts/notices.mjs` packages dependency, Teul, historical-source and APCA notices in each static build.

## Annotate the studio with Agentation

Run `npm --prefix web run feedback` from the repository root, then open **http://127.0.0.1:5179** on desktop. This starts the Vite development interface and the local Agentation receiver together. Stop any existing studio preview on 5179 first. Both listeners bind 127.0.0.1; the feedback receiver uses port 4747.

Click Agentation's bottom-right toolbar button, select an element, write a note, and click Add. Tell the agent to read your annotations when you are ready. `npm --prefix web run feedback:read` returns pending feedback for this studio origin, including the selected element and page context. The agent can acknowledge/resolve notes through Agentation's HTTP API after verifying a fix; a note is not itself proof that a change was made.

The official Agentation server stores notes locally in `~/.agentation/store.db`; the browser also retains annotations. Notes are not committed or uploaded. No global Codex/Claude configuration is changed. This task can read feedback through the local HTTP API without registering a new MCP server or restarting Codex. There is no background agent watcher.

The toolbar runs only with the feedback command and is excluded from production builds and ordinary development mode. The standalone static deployment has no annotation receiver. Copying formatted feedback remains available in the toolbar. Agentation is desktop-only.

Pinned integration: `agentation@3.0.2`, `agentation-mcp@1.2.0`. The receiver wrapper uses the pinned package's direct forwarding to Node's `listen` options to bind loopback; preserve its string representation because the package also interpolates the argument into URLs. Verify browser-to-server delivery and listener binding after upgrades. Setup reference: https://www.agentation.com/install.

## Give feedback with a Supercut walkthrough

Use a short screen-and-voice recording for overall direction, interaction sequences, and comparisons. Keep the cursor visible, pause over each element, and name it. Explain what happens, why it feels wrong, and what you want instead. For example: “This selected swatch looks muddy against the white card. Keep the original seed; change the supporting surface.” Show an example when a visual quality is hard to describe. Agentation remains useful for an exact element reference; using both is optional.

Share the recording link in the task with the intended scope, such as “Turn this walkthrough into a short change list and implement it.” The agent should retrieve the transcript and screen frames around each issue, connect them to the current interface, distinguish explicit requests from interpretation, implement the agreed scope, and return the changes with browser verification. Cursor position is visual evidence; it does not supply the DOM selector that Agentation captures. For motion, inspect several frames around the transition.

Supercut's recommended connection is remote MCP with OAuth:

```toml
[mcp_servers.supercut]
url = "https://mcp.supercut.ai/mcp"
```

After approving this addition to `~/.codex/config.toml`, run `codex mcp login supercut`, choose the workspace in the browser, and verify access by reading one supplied recording's transcript and frame. Configuration alone does not prove access. A fresh Codex session may be needed to discover newly configured tools. This repository does not register the connector, store credentials, or upload annotations. The REST API is available if a separate automated service is needed later.

Sources: [Supercut's Codex setup](https://supercut.ai/agents/mcp-setup-guides/codex) and [MCP tools](https://help.supercut.ai/en/articles/16107764-mcp-tools), checked 2026-09-25.
